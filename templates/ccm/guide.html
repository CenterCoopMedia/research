Report template kit

CCM report template

One JSON file and one Python script build a standalone report with paper texture, ink drawings, and a stage that changes as the reader scrolls.

A swatch repaints this page, so you can read a theme before you take it. It changes nothing in the kit: the theme block of report.json holds the five colors, and that block is what you copy into your own report.

Make a report

Four steps from a download to a page.

  1. Copy the folder for your new report. The download unpacks to a folder that already builds.

    unzip template.zip
cd CCM-report-template

  2. Edit report.json with a text editor. Every heading, paragraph, statistic, link, and color on the page comes from that one file.

  3. Run the build from the copied folder. Python 3.11 or later works with no packages to install.

    python3 build.py

  4. Open index.html in a browser. The export is one file and it opens from disk.

Build a second report beside the template by naming its content file and its output.

python3 build.py my-report.json --output ../my-report/index.html

To load the stylesheet and the script from this folder instead of embedding them, pass the base URL. That export needs the network; the default one does not.

python3 build.py report.json --output starter.html \
  --assets-url https://jamditis.com/ccm-report-template

Rebuild after each edit. Changes typed into the exported HTML disappear on the next build.

What you get

12 marks, five colors, four type presets.

The marks

Every drawing holds 12 marks. Stroke count, size, weight, and jitter come from the mark's own index, so each one is a sibling of the others and none is a copy. They are an illustration, not a chart.

The palette
  • paper #f6f3ebPage and card background
  • ink #292925Text, marks, primary button
  • accent #a33e36Highlights, numerals, focus ring
  • secondary #466958Connection lines and cover caption
  • wash #e7e4d9Dividers, code, methods band

Every other color on the page is mixed from these five, so a new theme moves the whole report and leaves no stranded gray behind.

The type

A story is only the beginning.

Display: the cover, the headings, the large numerals.

Follow the connections.

Body: the sentences, and the labels beside them.

Three roles carry the page, and a preset fills all three. Four presets ship with the kit. A report that names none of them sets in the reader's own faces and asks no font server for anything.

Type

Four presets, one line of JSON.

A preset names the display face, the body face and the label face at once, and every one of them carries a display weight of 800 or more. The files are latin subsets under fonts/, each with its OFL licence beside it, and the build writes the ones your preset needs into the page as data, so an export still opens from a disk with no network. The system preset embeds nothing.

system

The reader's own faces, and no file to download. The display weight is 800, which the stack draws where the face has it.

{
  "fonts": {
    "preset": "system"
  }
}

Layout

Two layouts for the same measure.

Both layouts set the reading column at 34em, so a line holds 62 to 66 characters in every preset. The wide layout moves that column to the left gutter and opens a rail beside it for the notes, the pull quotes and any figure or table you mark with "rail": true. Below 1000 pixels the rail folds into the column at the place you wrote each block, so a phone reads one column in both layouts.

reading

The centered column the kit shipped with. A note goes to the margin beside it where the window is wide enough, and to the foot of the section where it is not.

Section types

Twenty kinds of section, in any order.

Give every section a unique id that starts with a lowercase letter, such as key-findings. Use letters, digits, and hyphens. The ids main and top are reserved. The contents menu follows the order of the sections, and quote sections are left out of it because they carry no title.

TypeFields beyond type and id
summarytitle, text (under 100 words)
takeawayslabel, title, items (list of text, 2 to 5)
proselabel, title, paragraphs (list of text, or a block object)
stepslabel, title, items: each has title and text
glossarytitle, terms: each has term and definition
scrollylabel, title, optional center_label, steps
waterfalllabel, title, dataset (title, unit, totalSquares, status, source, caveat, groups)
findingslabel, title, items: each has value, title, text, and optional unit, note and trend
figurelabel, title, chart: kind, unit, value_format and the values the kind reads, caption, and optional source, note and rail
tabletitle, caption, columns: each has label, type and optional unit, rows, sort, and optional note, source and rail
quotetext, attribution
tabslabel, title, panels: each has label and paragraphs
accordionlabel, title, items: each has summary and paragraphs; optional exclusive
timelinelabel, title, events: each has date, title, text
imagesrc, alt, optional caption, credit, decorative, lightbox, and width of reading, figure or bleed
comparelabel, title, before and after: each has src, alt, label; optional caption
gallerylabel, title, items: each has src, alt, caption
diagramlabel, title, nodes: id, label; edges: from, to, optional label; layout of row, column or ring; optional caption
partnumber, title, optional deck
methodstitle, paragraphs, optional brief, sources: each has label, url

A scrolly section needs at least one step, and each step names a layout of scatter, groups, network, or orbit, a caption describing the state in plain text, and a highlight. The README.md in the download lists every field and what it accepts.

A compressed abstract with its own landmark, for the top of a report.

    In the wild

    Six examples built with the kit.

    Each page is built by build.py from the JSON file beside it, in one of the four themes, and each one opens from disk. Every sentence, name, number and result on all six is invented for a design showcase. The six links below go to the hosted copies, because the ZIP does not carry the folder.

    • Who covers the town?A full research report: a county-by-county count of the paid people who cover local government in New Jersey.
    • Saying soA research paper: how 60 invented newsrooms wrote their AI disclosures, and where on the page each notice sat.
    • Ninety days for one recordA multimedia feature: one public records request from the first email to the last of 212 pages.
    • A matter of scaleA scrolling waterfall chart with a built-in data editor and JSON and HTML downloads.
    • Five things the 2026 partner survey foundA one-page brief: what 214 invented partner newsrooms said they need next.
    • How a collaborative reporting project runsAn explainer: the eight months from the first phone call to publication day.

    The examples index holds the same six links and the description of each one.

    Download

    Take the kit.

    Download template.zip Read the sample report

    The ZIP holds the whole kit: build.py, package.py, report.json, report.css, report.js, favicon.svg, the fonts/ folder with the five faces and their licences, the built index.html, the hosted-asset starter.html, this guide and the template it is built from, README.md, and DESIGN.md. It leaves out the social image, because every published report needs its own.

    Four of those files open from here:

    • report.json holds the content of the sample report, including the waterfall chart, its data editor, and the end matter.
    • starter.html loads the stylesheet and the script from this folder.
    • README.md lists every field and what it accepts.
    • DESIGN.md states the design system and the rules it holds to.

    Every number, name and quotation in the sample report is invented. Replace the content, the notice, the header links and the template link with your own verified work before you publish.
